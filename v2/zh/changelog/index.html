    asmysql v2 变更日志¶

    本文档记录 asmysql v2 版本的所有变更。

    v2.7.0¶

    新功能 (New Features)¶

    • 包内 AI 开发 skill 与一键安装：新增包内 asmysql/_ai/ AI 资产（AGENTS.md 入口 + asmysql-dev skill 三件参考），随 wheel 分发、离线可得；python -m asmysql skill install --target claude 一键安装（--target 必填、项目级优先，支持 user: 前缀 / 多目标 / 自定义路径，--force 刷新），单一真源 + per-skill 软链 + 版本戳记自检
    • 文档站 AI 入口：新增 AI Development 双语页与站点根 /ai/ 版本无关资产（llms.txt 索引、llms-full.txt 中文全文、skill zip 与逐文件读取），根 /llms.txt 指针永远指向最新入口
    • PyPI 与 README 发现入口：README 新增 AI-Assisted Development / AI 辅助开发章节，PyPI 元数据新增 AI Docs 链接，asmysql/__init__.py 顶部新增 AI 入口模块 docstring

    范围边界¶

    • 不改 v1/v2 运行时行为与导出；零新增运行时依赖、不新增 console script；不做静默自动安装

    v2.6.0¶

    缺陷修复 (Bug Fixes)¶

    • Result 未正确关闭时的连接泄漏修复（Result.__del__）：已执行未关闭的 Result 被 GC 时，同步丢弃连接（关 transport，不发 COM_QUIT）并 pool.release() 完成池记账，发 ResourceWarning；连接不再被 Pool._used 永久钉住，泄漏满池后 acquire 挂起与 disconnect() 默认挂死均消除；丢弃而非归还复用，避免流式未读完的行污染下一个使用者

    行为变更 (Behavior Changes)¶

    • GC 安全网语义：被遗弃的未关闭 Result 不再永久泄漏；代价是连接不复用、未提交事务由服务端回滚（已 autocommit 数据不受影响）；仍被引用且未 close 的 Result 等待语义不变
    • ResourceWarning 措辞：改为「连接已丢弃（不复用），未提交事务将由服务端回滚」；disconnect_timeout 默认 None 保持不变

    文档用法标准化 (Usage Standardization)¶

    • 执行 SQL 仅推荐统一安全形式：async with、async for（含 break）、fetch_all()、iterate()、DDL/DML 自动释放；裸执行 + fetch 不 close 不再推荐（API 不删除，标准化落在文档层）
    • result.md 新增「标准用法」节；best-practices.md 新增 ❌ 反例；api.md 澄清 Result 不支持 await result、__call__ 重定位为内部入口、fetch 家族补使用约束、新增 __del__() 条目；faq.md disconnect 问答更新

    文档 (Documentation)¶

    • 双语文档同步更新（result/best-practices/api/faq）

    v2.5.0¶

    新功能 (New Features)¶

    • Engine.terminate()：同步强制清理连接池（幂等），不等待归还、立即关闭全部在用连接并掐断在途查询，best-effort 清理空闲连接；适用 atexit、同步 shutdown 钩子；清理后可重新 connect 复用
    • Engine.__del__ 安全网：未 disconnect 即被 GC 时发 ResourceWarning 并自动 terminate，不再依赖 Connection.__del__（警告噪音、循环 GC 延迟、loop 已关闭时 RuntimeError）

    行为变更 (Behavior Changes)¶

    • Result.pool 关闭后清空：类型 Final[Pool] → Optional[Pool]；close/无结果集自动释放后清空引用，缓存已关闭 Result 不再钉住 Pool 与事件循环（隐患 3）
    • 先 close 后执行报错：未执行的 Result 先 close 后再执行抛 RuntimeError；已执行 Result 重入 async with 仍为 no-op

    文档与测试 (Documentation & Testing)¶

    • 双语文档同步更新（connection/result/api/faq）
    • 新增 TestEngineTerminate、TestResultPoolRetention Mock 用例与 terminate 集成用例；真实 MySQL 程序级探针（在途查询掐断、服务端连接归零、__del__ 兜底、Pool 可回收）；全量 452 passed

    v2.4.0¶

    行为变更 (Behavior Changes)¶

    • result.error.__traceback__ 置为 None：错误存储时断开 traceback 帧链，消除「Result → 异常 → 栈帧 → Result」引用环；error_no/error_msg/query 不受影响
    • 活池跨事件循环明确报错：池未断开时在新事件循环调用 connect() / engine.pool / execute() 抛带清晰提示的 ConnectionError（此前为难懂的 RuntimeError 或静默误用）

    新功能 (New Features)¶

    • Engine 跨事件循环复用：内部连接锁随循环变化重建，原循环 disconnect 后可在新循环重新 connect（如多次 asyncio.run()）

    缺陷修复 (Bug Fixes)¶

    • 修复错误 traceback 引用环导致的内存驻留：长期持有 result.error（错误审计场景）不再连带驻留整个 Result 与栈帧局部变量；Result 不再依赖循环 GC 轮次才能回收
    • 修复 _connect_lock 把 Engine 绑死到首个发生竞争的事件循环：跨 asyncio.run() 复用 Engine 不再抛 RuntimeError: ... is bound to a different event loop

    文档与测试 (Documentation & Testing)¶

    • 双语文档同步更新（result/connection/faq/api）
    • 新增 TestErrorTracebackRetention、TestEngineCrossLoop Mock 用例与跨循环重连集成用例；全量 430 passed

    v2.3.0¶

    重大变更 (Behavior Changes)¶

    • 自动提交机制重构：连接池改为 autocommit=True（库内置，无配置参数），移除 SQL 关键词白名单；成功语句有事务即提交、失败语句即回滚；stream=True 写语句现在正确提交；不支持跨语句事务

    新功能 (New Features)¶

    • disconnect_timeout：disconnect 可选有限超时 + terminate 兜底（默认 None 无限等待，向后兼容）；取消路径必然收敛
    • execute_many([]) 显式告警：空列表不执行 SQL，发出 UserWarning，row_count=0

    缺陷修复 (Bug Fixes)¶

    • 修复多条写入静默丢失路径：流式写不提交、白名单漏判、COMMIT 失败被吞、init_sql 的 id(conn) 地址复用、ping 静默重连丢会话、流式游标关闭失败污染连接
    • 修复 CancelledError 连接泄漏：同步丢弃 + 重抛，不进 result.error
    • init_sql 失败丢弃连接，改用独立 buffered 游标执行

    文档与测试 (Documentation & Testing)¶

    • 双语文档同步更新（transaction/connection/result/faq/examples/api/index）；ClickHouse 示例改查询级 SETTINGS 子句（wait_for_async_insert=1）
    • M1-M33 Mock 矩阵 + 新增 MySQL/ClickHouse 集成测试，全量 339 passed；双后端实测探针与 mycli 独立落库核对通过

    v2.2.0¶

    新功能 (New Features)¶

    • AsMysql 构造式单例：以 (子类, 引擎对象) 为键复用实例，同一子类同一引擎恒返回同一实例，不同子类/引擎互不串扰
    • release() 注销：release(engine) 删除该引擎在所有子类下的条目，release() 清空全表；已断开引擎的旧条目在下次新建时惰性剔除

    行为变更 (Behavior Changes)¶

    • AsMysql(engine) 多次构造现在复用同一实例；依赖每次构造生成新实例的业务类需调整

    文档 (Documentation)¶

    • 在 business-logic.md、api.md 补充构造式单例与 release() 文档（中英文版本）

    测试 (Testing)¶

    • 新增 test_mock_asmysql_singleton.py，覆盖构造式单例、release() 语义与断连条目惰性清理

    v2.1.0¶

    新功能 (New Features)¶

    • 连接初始化 SQL（init_sql）：新增 init_sql 参数，支持在每条新 TCP 连接首次使用时自动执行预设 SQL，适用于 ClickHouse 异步插入配置、MySQL Session 变量设置等场景。使用 WeakKeyDictionary 追踪已初始化连接，完全向后兼容。

    重大变更 (Breaking Changes)¶

    • 自动提交机制重构：移除 auto_commit Engine 参数和 commit execute/Result 参数，改为基于 SQL 语句首关键词的自动提交机制（_should_commit()）。写操作自动 COMMIT，读操作不提交，stream 模式不提交
    • 移除 Engine stream 参数：stream 不再是 Engine 类属性，仅在 execute() 方法级别使用
    • 移除 Engine result_class 参数：result_class 不再是 Engine 类属性或构造参数，仅在 execute() / execute_many() 方法级别使用，默认值为 tuple

    缺陷修复 (Bug Fixes)¶

    • 修复 6 个连接泄漏问题：fetch_all() 自定义类型泄漏、错误后双重释放、async for + break 泄漏、非 MySQLError 异常泄漏、__del__ 崩溃、DDL/DML 语句未释放连接
    • 修复 5 个逻辑错误：echo_sql_log URL 解析、or 运算符覆盖 falsy 值、并发竞态条件、pool 空值传递、泛型参数语义错误
    • 修复 5 个中低危问题：release_connections() 空值检查、@lru_cache 内存泄漏、error_msg 格式化、iterate() 检查不一致、属性访问崩溃

    文档 (Documentation)¶

    • 修正首页示例代码中不存在的 API
    • 在 connection.md、api.md、examples.md 中同步添加 init_sql 文档（中英文版本）
    • 重写事务控制文档，描述基于 SQL 语句类型的自动提交机制
    • 修正 API 文档签名：移除不存在的 close/commit 参数

    测试 (Testing)¶

    • 新增 test_engine_init_sql.py，覆盖 init_sql 核心功能与边界场景
    • 重写集成测试 engine fixture，通过 init_sql=USE <test_db> 自动选择测试数据库
    • 移除 test_mock_engine.py 中与 Engine result_class 相关的测试用例

    v2.0.0¶

    重大变更 (Breaking Changes)¶

    v2.0.0 是一个完全重构的版本，与 v1 版本不兼容。主要变更包括：

    • 架构重构：分离 Engine 和 AsMysql 类，新增独立的 Engine 类处理 MySQL 连接和执行语句
    • Result 类变更：Result.err 属性重命名为 Result.error
    • API 变更：连接方式从自动连接改为显式创建 Engine 并调用 connect()

    新功能 (New Features)¶

    • Engine 类：全新的连接引擎类，支持 URL 连接字符串、连接状态监控、灵活的连接管理
    • Result 类增强：支持错误信息访问（error_no、error_msg）、流式查询、上下文管理器、异步迭代器、自定义结果类型
    • 执行方法增强：execute() 方法支持 stream、result_class 等参数，支持多种调用方式
    • 类型提示：完整的类型提示支持，支持泛型类型（Result[T]）
    • 测试：新增 pytest 测试套件，覆盖主要功能场景

    更新 (Updates)¶

    • 包管理工具：使用 uv 作为包管理工具
    • 代码质量：改进代码结构、错误处理和文档字符串

    核心特性 (Features)¶

    v2 版本保留了 v1 版本的核心特性：

    1. 简易使用：asmysql 是对 aiomysql 封装的简易使用库
    2. 连接池管理：自动管理 MySQL 连接池，支持重连机制
    3. 错误处理：全局自动捕获 MysqlError 错误
    4. 执行与获取分离：执行 SQL 语句和获取结果分离
    5. 类型提示：完整的 Python 类型提示支持
    6. 业务逻辑开发：直接继承 AsMysql 类进行逻辑开发
