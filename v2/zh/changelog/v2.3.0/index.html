    v2.3.0 变更详情¶

    主题：写入提交可靠性修复。修复 v2 多条「执行无异常、数据未落库」的静默丢失路径，保持 result.error 静默契约不变。 设计文档：asmysql_v2_commit_reliability_design.md；实测探针与测试报告见仓库根 asmysql_v2_commit_reliability_probe_report.md、asmysql_v2_commit_reliability_test_report.md。

    重大变更 (Breaking Changes)¶

    1. 自动提交机制重构：服务端 autocommit + 事务状态兜底¶

    • 连接池由 autocommit=False（硬编码）改为 autocommit=True（库内置行为，不新增任何配置参数）；正常语句由服务端自动提交。
    • 移除 SQL 首关键词白名单（_WRITE_KEYWORDS / _should_commit()），不再解析 SQL 文本判断读写；服务端事务状态（IN_TRANS 标志位）是唯一事实来源。
    • 统一规则：成功语句有未结束事务即 COMMIT，失败语句即 ROLLBACK（失败判定含 autocommit 被关闭的补判定）。
    • 若后端拒绝 SET AUTOCOMMIT 握手，库内部自动降级为服务端默认（autocommit=None）并发出 RuntimeWarning，对调用方透明。

    行为变化对照：

    场景 变更前 变更后
    stream=True + INSERT/UPDATE/DELETE 不提交，连接归还时被回滚（静默丢数据） 提交，正常落库
    WITH ... UPDATE/DELETE、# 注释开头写语句、OPTIMIZE/DO 等 白名单漏判，不提交 按服务端事务状态提交
    普通 INSERT（非 stream） 客户端 COMMIT 服务端自动提交，客户端不重复 COMMIT
    SELECT 后连接归还 事务残留，连接被 aiomysql 关闭 事务结束后归还，连接真正复用
    失败语句 可能残留事务 ROLLBACK，部分写入绝不提交
    手动 BEGIN / START TRANSACTION 行为不明确 执行后立即被提交（v2 不支持跨语句事务）

    2. 提交/回滚失败的连接处置¶

    COMMIT/ROLLBACK 失败、游标关闭失败、init_sql 失败的连接一律丢弃（关闭后仅做池记账），永不回池复用；错误写入 result.error，不抛异常。

    新功能 (New Features)¶

    1. disconnect_timeout 配置（默认 None，向后兼容）¶

    Engine 新增 disconnect_timeout: Optional[float] = None（类属性默认值、构造参数、URL 查询参数均可，URL 中 none 表示 None）：

    • None（默认）：无限等待所有连接归还，与旧版行为完全一致；
    • 有限值：优雅等待超时后发出 ResourceWarning 并强制 terminate 全部在用连接，必然收敛；在途查询收到 error_no=2013；
    • <= 0：不等待，立即 terminate；
    • disconnect 自身被取消时同样 terminate 并重抛，取消路径必然收敛。

    2. execute_many([]) 显式告警¶

    空参数列表不再静默零执行：不获取连接、不发送 SQL，发出 UserWarning，row_count=0、last_rowid=None。

    缺陷修复 (Bug Fixes)¶

    • 流式写语句静默丢失：stream=True 的写语句现在正确提交（无结果集立即提交，有结果集延迟到游标关闭）。
    • 关键词白名单漏判：WITH、注释开头、OPTIMIZE/ANALYZE/DO 等语句不再漏提交。
    • COMMIT 失败被吞：提交失败写入 result.error 并丢弃连接，不再带事务归还。
    • init_sql 跟踪用 id(conn) 的 GC 地址复用：改为 WeakSet 按连接对象身份跟踪，新连接必定重新执行 init_sql。
    • ping() 静默重连丢会话：移除 close() 与执行路径中的 ping()（真正释放锁的是事务结束，ping 无此能力且会重建 TCP）。
    • 流式游标未读完即 close 的协议污染：游标关闭失败即丢弃连接，不再 COMMIT。
    • init_sql 失败连接半初始化回池：失败即丢弃；init_sql 改用独立 buffered 游标执行，避免流式游标 Commands out of sync。
    • CancelledError 连接泄漏：取消时同步丢弃连接并归还槽位，CancelledError 重抛（不进入 result.error）；acquire 排队阶段取消可安全重试，acquire 之后取消的 Result 整体废弃。__anext__ 不再把取消吞成 StopAsyncIteration。
    • 非 MySQLError 后无法重试：移除 finally 无条件置位 __executed，acquire 阶段的非 MySQLError 异常不再阻止同一 Result 重试。
    • disconnect() 死等：提供可选有限超时 terminate 兜底（见新功能 1），默认行为不变。

    语义边界（需知悉）¶

    • 取消 ≠ 回滚：取消只打断客户端等待；autocommit=1 下服务端已执行完的写入已提交落库。
    • 不支持跨语句事务：每次 execute() 独立提交。
    • ClickHouse 等非事务后端不置事务状态位，成功路径零 COMMIT；失败路径会发一条被接受的无害 ROLLBACK（实测 26.5.1）。
    • BOM 开头的语句被 MySQL 8 服务端拒绝（1064），错误可见而非静默丢失；MySQL 8 前置 WITH ... INSERT 为非法语法（CTE INSERT 须后置）。
