# 文档翻译技能

## 功能概述

将源语言文档翻译成目标语言文档，**完全保持**源文档的格式、结构和布局。

## 支持的文档命名形式

1. **后缀形式**：文件名后缀区分语言
   - `README_zh.md` → `README.md`
   - `CHANGELOG_zh.md` → `CHANGELOG.md`

2. **目录形式**：目录名区分语言
   - `zh/README.md` → `en/README.md`
   - `zh/api.md` → `en/api.md`

## 核心规则

### 格式完全一致（最高优先级）

- **行数**：目标文档总行数必须与源文档完全一致
- **空行**：每个空行位置必须完全对应
- **空格/缩进**：代码块、注释、文本中的空格和缩进必须完全一致
- **换行**：每行的换行位置必须完全一致

### 结构完全一致

- 标题层级（`#`、`##`、`###`）保持一致
- 代码块开始/结束位置、语言标识符保持一致
- 有序/无序列表格式保持一致
- 粗体/斜体/链接等 Markdown 标记保持一致

### 内容翻译规则

| 内容类型 | 处理方式 |
|---------|---------|
| 普通文本 | 翻译 |
| 代码块内容 | **不翻译**（代码、注释、字符串均保持不变） |
| URL / 链接地址 | **不翻译** |
| 技术术语 | 保持准确，必要时保留原文或使用标准翻译 |
| Markdown 语法标记 | **不修改**（`**`、`#`、`` ` `` 等保持原样） |

## 工作流程

执行翻译时，严格按以下步骤进行：

### 步骤 1：读取文档

```
Task Progress:
- [ ] 读取源文档（完整内容）
- [ ] 读取目标文档（完整内容）
- [ ] 识别文档命名形式（后缀/目录）
```

### 步骤 2：逐行对比分析

- 识别每一行的类型（文本、代码、空行、标题、列表等）
- 标记需要翻译的行 vs 需要保持原样的行

### 步骤 3：翻译并写入

- 逐行翻译，仅替换文本内容
- 保持所有格式元素不变
- 写入目标文件

### 步骤 4：验证一致性

翻译完成后必须验证：

- [ ] 总行数一致
- [ ] 空行位置一致
- [ ] 代码块格式一致
- [ ] 标题层级一致

## 本项目文档结构

本项目的 mkdocs 双语文档采用**目录形式**：

```
mkdocs/v2/docs/
├── zh/          # 中文文档（源语言）
│   ├── index.md
│   ├── quickstart.md
│   ├── api.md
│   └── ...
└── en/          # 英文文档（目标语言）
    ├── index.md
    ├── quickstart.md
    ├── api.md
    └── ...
```

翻译时，源文档为 `zh/` 下的文件，目标文档为 `en/` 下对应文件。

## 使用示例

### 示例 1：翻译单个文档（目录形式）

```
请根据中文文档 @mkdocs/v2/docs/zh/quickstart.md 翻译成英文文档，写入 @mkdocs/v2/docs/en/quickstart.md。

要求：完全对照中文文档来，包括空行、空格等，一字不差每行都修改过来。
```

### 示例 2：翻译单个文档（后缀形式）

```
请根据中文文档 @README_zh.md 翻译成英文文档，写入 @README.md。

要求：完全对照中文文档来，包括空行、空格等，一字不差每行都修改过来。
```

### 示例 3：批量翻译

```
请将 mkdocs/v2/docs/zh/ 下的所有文档翻译成英文，写入 mkdocs/v2/docs/en/ 对应文件。
```

## 注意事项

1. **不要删除或添加空行**：即使看起来多余，也要保持源文档的空行结构
2. **不要修改代码**：代码块中的任何内容都不应该被翻译或修改
3. **不要改变格式标记**：Markdown 语法标记必须保持原样
4. **大文件分段处理**：如果文档很长，分段读取和写入，确保不遗漏任何行
