### 新功能 (New Features)

#### 1. 连接初始化 SQL（`init_sql`）

新增 `init_sql` 参数，支持在每条新 TCP 连接首次使用时自动执行预设 SQL。适用于 ClickHouse 异步插入配置、MySQL Session 变量设置等场景。

**背景**：

在 ClickHouse 等数据库中，`SET` 语句的作用域为 TCP 连接级别。之前每次执行 `INSERT` 前都需要手动执行 `SET` 语句来配置异步插入等参数，冗余且低效。`init_sql` 特性将这一能力下沉到引擎层，实现连接级自动化。

**工作原理**：

- `connect()` 创建连接池后，自动包装 `pool.acquire()` 方法
- 使用 `weakref.WeakSet` 追踪已初始化的 Connection 对象
- 新连接首次 acquire 时自动执行 `init_sql`，后续复用同一连接时跳过
- 连接被 `pool_recycle` 回收重建后，新连接会重新执行 `init_sql`
- `init_sql` 执行失败时异常向上抛出，保证错误可捕获

**使用方式**：

```python
from asmysql import Engine

# 通过关键字参数设置
engine = Engine(
    host="192.168.62.195",
    port=9004,
    user="default",
    password="",
    init_sql=(
        "SET async_insert = 1, wait_for_async_insert = 0, "
        "async_insert_busy_timeout_ms = 1000, "
        "max_execution_time = 30"
    ),
)
await engine.connect()

# 通过 URL 参数设置
engine = Engine(
    url="mysql://user:pass@127.0.0.1:3306/?init_sql=SET SESSION wait_timeout=600"
)
await engine.connect()
```

**向后兼容**：

`init_sql` 默认值为 `None`，不传时行为与 v2.0.0 完全一致，不影响现有代码。

### 缺陷修复 (Bug Fixes)

- **修复 `fetch_all()` 自定义结果类型连接泄漏**：当 `result_class` 为自定义类（如 Pydantic BaseModel）时，`return _data` 在 `close()` 之前退出，每次调用泄漏一个连接。已统一 `return` 路径确保 `close()` 始终执行
- **修复查询错误后 `close()` 双重释放**：`__call__()` 的 except 分支关闭 cursor 并释放连接后未将 `__cursor` 置空，后续 `close()` 会再次释放同一连接，破坏连接池计数。已在 except 中添加 `self.__cursor = None`
- **修复 `_apply_pool_init_hook` 中 `init_sql` 失败连接泄漏**：`cursor.execute(init_sql)` 异常时连接既未返回调用者也未释放回池，永久消耗连接池槽位。已添加 `except` 分支在异常时 `pool.release(conn)`
- **修复 `async for` + `break` 连接泄漏**：`__aiter__` 返回 `self` 导致 `break` 后 `__anext__` 不再被调用，连接无法释放。已重写为 async generator + `try/finally` 模式确保任何退出路径都触发 `close()`
- **修复 `Result.__call__()` 仅捕获 `MySQLError` 导致连接泄漏**：`OSError`、`asyncio.CancelledError` 等非 MySQL 异常未被捕获，已获取的连接不会释放。已改为 `except Exception` 并在非 MySQL 错误时 re-raise
- **修复 `__del__` 安全网崩溃**：`__del__` 在 GC 期间无错误处理，`self.pool` 可能为 None 导致 `AttributeError`。已添加 `try/except` 和 pool 空值检查
- **修复 `auto_commit`/`echo_sql_log` URL 参数无法设为 False**：`?auto_commit=false` 被解析为 `True`（非空字符串为 truthy）。已改为正确解析布尔字符串（`true/1/yes` → True，其他 → False）
- **修复 `or` 运算符覆盖合法 falsy 值**：`Engine(min_pool_size=0)` 的 `0` 被 `or` 覆盖为默认值 `1`，`pool_recycle=0.0`、`connect_timeout=0` 同理。已统一改为 `x if x is not None else default`
- **修复 `connect()`/`disconnect()` 并发竞态条件**：多个协程同时调用可创建多个连接池或对同一连接池双重关闭。已添加 `asyncio.Lock` 保护
- **修复 `execute()` 传入 `self.__pool`（可能为 None）而非 `self.pool`（含空值检查）**：未连接时 Result 获得 None pool，错误延迟到 await 时才报令人困惑的 `AttributeError`。已改用 `self.pool` 属性
- **修复 `Result[type[T]]` 泛型参数语义错误**：应为 `Result[T]`（行数据类型），而非 `Result[type[T]]`（元类型）。已修正 `execute()` 和 `execute_many()` 中的泛型参数
- **修复 `release_connections()` 缺少空值检查**：未连接时调用抛出 `AttributeError`。已添加 `if self.__pool` 前置检查
- **移除 `@lru_cache` 装饰器**：`Engine`、`Result`、`AsMysql` 的 `__repr__`/`__str__`/`error_no`/`error_msg` 上的 `@lru_cache` 持有对 `self` 的强引用，阻止实例被 GC 回收。已移除 `__repr__`/`__str__` 的缓存，将 `error_no`/`error_msg` 改为 `@cached_property`
- **修复 `error_msg` 未使用 `err_msg()` 格式化**：v2 直接取 `error.args[1]`，丢失了 v1 中对空字符串的回退处理（`err.__doc__`）。已改为调用 `err_msg()` 函数
- **修复 `iterate()` 使用 truthiness 检查不一致**：`if data:` 将空元组视为 falsy 导致迭代提前终止，而其他方法使用 `if data is not None:`。已统一为 `is not None` 检查
- **修复 `__aexit__` 在有错误时跳过 `close()`**：`async with` 退出时如果 `self.error` 不为 None 则不调用 `close()`，未来代码变更可能引入泄漏。已改为始终调用 `close()`
- **修复 `row_count`/`last_rowid`/`row_number` 在 close 后 `AttributeError`**：cursor 被置空后访问这些属性会崩溃。已添加 `self.__cursor is None` 检查，返回 `None`
- **修复 `fetch_one()` 数据耗尽时忽略 `close=False`**：即使传了 `close=False`，fetchone 返回 None 时仍会强制关闭。已改为仅在 `__conn_autoclose` 为 True 时关闭
- **新增自定义异常类**：定义 `AsMysqlError`、`ConnectionError`、`QueryError` 异常层级，`Engine.connect()` 和 `pool` 属性使用自定义 `ConnectionError` 而非内建类型
- **导出 `EngineStatus` 和异常类**：`v2/__init__.py` 和顶层 `asmysql/__init__.py` 现在导出 `EngineStatus`、`AsMysqlError`、`ConnectionError`、`QueryError`

### 测试 (Testing)

- 新增 `test_engine_init_sql.py` 测试文件，包含 15 个测试用例，覆盖：
  - `init_sql` 默认值与向后兼容性
  - 构造参数和 URL 参数设置
  - 新连接首次 acquire 自动执行 `init_sql`
  - 同一连接后续 acquire 不重复执行（WeakSet 追踪）
  - 多条连接各自独立初始化
  - `init_sql` 执行失败时异常传播
  - 连接被 GC 回收后新连接重新初始化
  - 多次 `connect()` 不重复包装
- 重写集成测试 `engine` fixture，通过 `init_sql=USE <test_db>` 在每条连接池连接上自动选择测试数据库，使测试在 Engine v2 无默认数据库参数（`db`）的情况下正常工作
