### New Features

#### 1. Connection Init SQL (`init_sql`)

Added `init_sql` parameter to automatically execute preset SQL on each new TCP connection's first use. Ideal for ClickHouse async insert configuration, MySQL session variable setup, and similar scenarios.

**Background**:

In databases like ClickHouse, `SET` statements are scoped at the TCP connection level. Previously, `SET` had to be manually executed before every `INSERT` to configure async insert parameters, which was redundant and inefficient. The `init_sql` feature moves this capability down to the engine layer for automatic per-connection initialization.

**How It Works**:

- After `connect()` creates the pool, `pool.acquire()` is automatically wrapped
- Uses `weakref.WeakSet` to track initialized Connection objects
- Executes `init_sql` on first acquire of a new connection; skips on subsequent reuses
- When a connection is recycled via `pool_recycle`, the new connection re-executes `init_sql`
- If `init_sql` execution fails, the exception propagates upward for proper error handling

**Usage**:

```python
from asmysql import Engine

# Via keyword argument
engine = Engine(
    host="192.168.62.195",
    port=9004,
    user="default",
    password="",
    init_sql=(
        "SET async_insert = 1, wait_for_async_insert = 0, "
        "async_insert_busy_timeout_ms = 1000, "
        "max_execution_time = 30"
    ),
)
await engine.connect()

# Via URL parameter
engine = Engine(
    url="mysql://user:pass@127.0.0.1:3306/?init_sql=SET SESSION wait_timeout=600"
)
await engine.connect()
```

**Backward Compatible**:

`init_sql` defaults to `None`. When not provided, behavior is identical to v2.0.0 — no impact on existing code.

### Bug Fixes

- **Fix `fetch_all()` connection leak for custom result types**: When `result_class` is a custom class (e.g., Pydantic BaseModel), `return _data` exited before `close()`, leaking one connection per call. Unified return path to ensure `close()` always executes
- **Fix double connection release after query error**: `__call__()` except branch closed cursor and released connection but didn't nullify `__cursor`, causing subsequent `close()` to release the same connection again, corrupting pool accounting. Added `self.__cursor = None` in except block
- **Fix `_apply_pool_init_hook` connection leak on `init_sql` failure**: When `cursor.execute(init_sql)` raised, the connection was neither returned to the caller nor released to the pool, permanently consuming a pool slot. Added `except` branch to `pool.release(conn)` on failure
- **Fix `async for` + `break` connection leak**: `__aiter__` returned `self`, so after `break`, `__anext__` was never called again and the connection was never released. Rewritten as async generator with `try/finally` to ensure cleanup on any exit path
- **Fix `Result.__call__()` only catching `MySQLError` causing connection leak**: Non-MySQL exceptions (`OSError`, `asyncio.CancelledError`) were uncaught, leaving acquired connections unreleased. Changed to `except Exception` with re-raise for non-MySQL errors
- **Fix `__del__` safety net crashes**: `__del__` during GC had no error handling and `self.pool` could be `None`, causing `AttributeError`. Added `try/except` and pool null check
- **Fix `auto_commit`/`echo_sql_log` URL parameters cannot be set to `False`**: `?auto_commit=false` was parsed as `True` (non-empty string is truthy). Now correctly parses boolean strings (`true/1/yes` → True, others → False)
- **Fix `or` operator overriding legitimate falsy values**: `Engine(min_pool_size=0)` had `0` overridden to default `1` by `or`; same for `pool_recycle=0.0`, `connect_timeout=0`. Unified to `x if x is not None else default`
- **Fix `connect()`/`disconnect()` concurrent race conditions**: Multiple concurrent coroutines could create multiple pools or double-close the same pool. Added `asyncio.Lock` protection
- **Fix `execute()` passing `self.__pool` (possibly None) instead of `self.pool` (with null check)**: Disconnected calls produced Result with None pool, failing with confusing `AttributeError` on await. Now uses `self.pool` property
- **Fix `Result[type[T]]` generic parameter semantic error**: Should be `Result[T]` (row data type), not `Result[type[T]]` (metatype). Corrected in both `execute()` and `execute_many()`
- **Fix `release_connections()` missing null check**: Called before connect(), raised `AttributeError`. Added `if self.__pool` guard
- **Remove `@lru_cache` decorators**: `@lru_cache` on `__repr__`/`__str__`/`error_no`/`error_msg` of `Engine`, `Result`, `AsMysql` held strong references to `self`, preventing GC. Removed caching from `__repr__`/`__str__`, converted `error_no`/`error_msg` to `@cached_property`
- **Fix `error_msg` not using `err_msg()` formatting**: v2 directly accessed `error.args[1]`, losing v1's fallback for empty strings (`err.__doc__`). Now calls `err_msg()` function
- **Fix `iterate()` truthiness check inconsistency**: `if data:` treated empty tuples as falsy, prematurely terminating iteration, while other methods used `if data is not None:`. Unified to `is not None` check
- **Fix `__aexit__` skipping `close()` on error**: `async with` exit skipped `close()` when `self.error` was set, potential leak source if code changes. Now always calls `close()`
- **Fix `row_count`/`last_rowid`/`row_number` `AttributeError` after close**: Accessing these properties after cursor was nullified caused crashes. Added `self.__cursor is None` guard, returning `None`
- **Fix `fetch_one()` ignoring `close=False` on data exhaustion**: Even with `close=False`, fetchone returning None forced a close. Now only closes when `__conn_autoclose` is True
- **Add custom exception classes**: Defined `AsMysqlError`, `ConnectionError`, `QueryError` hierarchy. `Engine.connect()` and `pool` property now use custom `ConnectionError` instead of built-in
- **Export `EngineStatus` and exception classes**: `v2/__init__.py` and top-level `asmysql/__init__.py` now export `EngineStatus`, `AsMysqlError`, `ConnectionError`, `QueryError`
